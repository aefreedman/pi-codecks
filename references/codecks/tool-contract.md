# Codecks Tool Contract

Bulk create and update calls should begin with `dryRun: true`. Both apply operations must include the matching dry run's `previewFingerprint` as `expectedPreviewFingerprint`; this validation checkpoint is mandatory. Exact authorization in the user's request covers that matching apply without a second interaction; request another checkpoint only when previewed scope differs. Apply is sequential. Each detailed bulk result echoes an optional caller `correlationKey` unchanged; it is a row-mapping value, not an idempotency key. `indeterminate` means a request may have reached Codecks and must not be retried automatically. `definitely_unsent` means no request was made for that record.

Bulk create validates and normalizes requested cards but does not do duplicate discovery, account fallback scans, post-create verification, or hidden cosmetic reads. Call `codecks_card_search` separately when likely-match review is needed. Both compact responses return counts, metrics, exceptional records, and a temporary sanitized JSON artifact path. The artifact contains complete normalized and dispatch-returned per-record details. Artifact-write failure is diagnostic only and does not alter mutation certainty. Bulk update's `continueOnError` continues only after definitely rejected non-429 failures; rate-limit and ambiguous outcomes stop the batch.

Every physical HTTP request passes the shared 40-requests-per-five-seconds rolling gate. Local waits are cancellable and publish immediate, once-per-second transient progress. Only an HTTP 429 can establish a server cooldown; valid Codecks numeric-millisecond or HTTP-date Retry-After values are bounded to fifteen seconds, while missing, malformed, negative, non-finite, and over-budget values return structured sanitized rate-limit diagnostics. Both bulk operations may retry only a definitely rejected HTTP 429, at most twice before stopping after three consecutive 429 responses; timeouts, network loss, cancellation, and ambiguous mutation failures are never retried. Results expose bounded physical-request, local/server-wait, retry, and continuation-safe metrics.

Velocity retrieval and reporting are separate contracts. `codecks_velocity_observations_update` atomically updates a caller-owned, organization-scoped JSON cache of completed-Run snapshots and delivered-card observations. Incremental refresh defaults to a 10-day overlap, and interval-level coverage records whether each factual stream is complete. `codecks_velocity_report` consumes that cache without network requests and expands every transformation into provenance.

`calendar_delivered` is the `standard_velocity` default and includes delivered cards outside Runs. `run_attributed` uses completed-Run `finishStats` and models multi-week totals over calendar days. Missing Run statistics and card estimates remain distinct from observed zero. Configuration filters use exact stable IDs or unambiguous exact names. `excludeDecks` accepts exact deck IDs or unambiguous titles (for example `Test`) for calendar-delivered reports and is rejected for Run-attributed snapshots, which cannot safely subtract deck-level effort.

Mutation titles, content, tags, and Deck descriptions reject U+FFFD and unpaired UTF-16 surrogates at the tool boundary. This prevents known-corrupt input from being written; it does not diagnose upstream encoding conversion.
