# pi-codecks tool contract

Use `codecks_tool_search` to activate the smallest sufficient specialized capability. Use `codecks_deck_get` to read a Deck description and `codecks_deck_update` only for an explicit description mutation; `codecks_query` is a read-only fallback for unsupported gaps.

Bulk create and update calls should begin with `dryRun: true`. Apply is sequential. Each result echoes an optional caller `correlationKey`; `actionKey` is a reconciliation diagnostic, not an idempotency key. `indeterminate` means a request may have reached Codecks and must not be retried automatically. `definitely_unsent` means no request was made for that record. A successful create remains `certainty: "dispatch_returned"` even when an optional identity read is missing, mismatched, or fails.

Bulk create duplicate discovery is credential-visible only: it checks cards accessible through the configured credential at scan time, not deleted or inaccessible cards. It uses at most four title-contains probes before a bounded account fallback, then exact-title and Deck/milestone scope matching on the client. `duplicatePolicy: "required"` blocks incomplete evidence; apply defaults to `"best_effort"`, which proceeds only when incompleteness is a scan-limit result and reports it; `"skip"` explicitly performs no discovery. API, cancellation, timeout, and queue failures are always blocking. Parent-local `required` is unavailable. `duplicateLimit: 0` omits candidates but still discovers.

Dry-run defaults to `outputMode: "detailed"`, response schema v1. Apply defaults to compact response schema v2 with correlation/status/certainty, returned `cardRef`/card ID, aggregate discovery metadata, and bounded warnings. Credential-free regression budgets for complete compact JSON tool strings are 4 cards ≤4,200 UTF-8 bytes, 34 cards ≤19,000 bytes, and 100 cards ≤52,000 bytes. Use explicit `outputMode: "detailed"` for `normalizedRequested`, fingerprints, raw dispatch data, compatible `created`, and verification diagnostics. Compact results intentionally omit those duplicated fields.

`verification: "none"` is the default and performs no post-create reads. `verification: "identity"` makes at most one exact read per identifiable dispatch identity and labels `verificationCheckedFields`; `identity_verified`, `not_found`, `mismatch`, `read_failed`, and `not_identifiable` do not alter create certainty. Dispatch identities are useful references, not proof of every persisted card field.

Mutation titles, content, tags, and Deck descriptions reject U+FFFD and unpaired UTF-16 surrogates at the tool boundary. This prevents known-corrupt input from being written; it does not diagnose upstream encoding conversion.
