# pi-codecks tool contract

Use `codecks_tool_search` to activate the smallest sufficient specialized capability. Use `codecks_deck_get` to read a Deck description and `codecks_deck_update` only for an explicit description mutation; `codecks_query` is a read-only fallback for unsupported gaps.

Bulk create and update calls should begin with `dryRun: true`. Apply is sequential. Each result echoes an optional caller `correlationKey`; `actionKey` is a reconciliation diagnostic, not an idempotency key. `indeterminate` means a request may have reached Codecks and must not be retried automatically. `definitely_unsent` means no request was made for that record. A successful create remains `certainty: "dispatch_returned"` even when an optional identity read is missing, mismatched, or fails.

Bulk create duplicate discovery is credential-visible only: it includes accessible archived cards when returned, but excludes deleted cards and inaccessible Private cards, which cannot be claimed absent. It uses at most four logical title-contains probes (not four paginated HTTP requests) before a bounded account fallback, then exact-title and Deck/milestone scope matching on the client. Fallback is eligible only for a semantic title-filter rejection, exceeded logical-probe budget, or incomplete title probe; transport/auth/rate/cancel/timeout/queue failures always block. `duplicatePolicy: "required"` blocks incomplete evidence; apply defaults to `"best_effort"`, which proceeds only when incompleteness is a scan-limit result and reports it; `"skip"` explicitly performs no discovery. Parent-local required apply is unavailable; default and explicit-required dry-runs return a no-create detailed preview with `parent_local_required_unavailable`. `duplicateLimit: 0` omits candidates but still discovers.

Dry-run defaults to `outputMode: "detailed"`, response schema v1. Apply defaults to compact response schema v2 with correlation/status/certainty, returned `cardRef`/card ID, aggregate discovery metadata, and bounded warnings. Discovery totals aggregate title and fallback stages; bounded stage metadata retains their individual totals. Credential-free regression budgets for complete compact JSON tool strings are 4 cards ≤4,200 UTF-8 bytes, 34 cards ≤19,000 bytes, and 100 cards ≤52,000 bytes. Use explicit `outputMode: "detailed"` for `normalizedRequested`, fingerprints, raw dispatch data, and compatible `created`. Compact results intentionally omit those duplicated fields but retain verification outcomes.

`verification: "none"` is the default and performs no post-create reads. `verification: "identity"` makes one non-retrying exact read per identifiable dispatch identity, labels only identity components actually compared in `verificationCheckedFields`, and uses `verificationObservedIdentity` for neutral observed values. `persistedVerified` is retained only for `identity_verified` compatibility. `identity_verified`, `not_found`, `mismatch`, `read_failed`, and `not_identifiable` do not alter create certainty. Dispatch identities are useful references, not proof of every persisted card field.

Velocity retrieval and reporting are separate contracts. `codecks_velocity_observations_update` atomically updates a caller-owned, organization-scoped JSON cache of completed-Run snapshots and delivered-card observations. Incremental refresh defaults to a 10-day overlap, and interval-level coverage records whether each factual stream is complete. `codecks_velocity_report` consumes that cache without network requests and expands every transformation into provenance.

`calendar_delivered` is the `standard_velocity` default and includes delivered cards outside Runs. `run_attributed` uses completed-Run `finishStats` and models multi-week totals over calendar days. Missing Run statistics and card estimates remain distinct from observed zero. Configuration filters use exact stable IDs or unambiguous exact names. `excludeDecks` accepts exact deck IDs or unambiguous titles (for example `Test`) for calendar-delivered reports and is rejected for Run-attributed snapshots, which cannot safely subtract deck-level effort.

Mutation titles, content, tags, and Deck descriptions reject U+FFFD and unpaired UTF-16 surrogates at the tool boundary. This prevents known-corrupt input from being written; it does not diagnose upstream encoding conversion.
